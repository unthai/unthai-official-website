  <action>
    **Owner performs in Cloudflare Dashboard:**

    1. Cloudflare Dashboard → unth.ai → Rules → Transform Rules
    2. Click "Modify Response Headers" tab
    3. Click "Create rule"

    **Rule configuration:**

    **Rule name:** `Security headers`

    **"When incoming requests match" section:**
    - Select: "All incoming requests" (no filter expression needed — leave the expression field empty or set to the default "All incoming requests" option)

    **"Then" section — Set header operations:**
    Add exactly FOUR "Set" operations (click "+ Add" for each):

    | Operation | Header name | Value |
    |-----------|-------------|-------|
    | Set | `X-Frame-Options` | `SAMEORIGIN` |
    | Set | `X-Content-Type-Options` | `nosniff` |
    | Set | `Permissions-Policy` | `geolocation=(), microphone=(), camera=(), payment=()` |
    | Set | `Referrer-Policy` | `strict-origin-when-cross-origin` |

    **Important:**
    - Use "Set" (not "Add" or "Remove") for all four — "Set" overwrites any existing value, "Add" appends a duplicate
    - Do NOT add a fifth header for `Content-Security-Policy` — see RESEARCH.md Pitfall 3 (breaks CF challenge pages)
    - Do NOT add `Strict-Transport-Security` here — that is handled by the HSTS panel in Task 3

    5. Click "Save and Deploy"
    6. Wait 30 seconds for deployment to propagate

    **Verify immediately after save:**
    ```bash
    curl -sI https://unth.ai | grep -iE "x-frame|x-content|permissions|referrer"
    # Expected (4 lines):
    # x-frame-options: SAMEORIGIN
    # x-content-type-options: nosniff
    # permissions-policy: geolocation=(), microphone=(), camera=(), payment=()
    # referrer-policy: strict-origin-when-cross-origin
    ```
  </action>

  <how-to-verify>
    ```bash
    curl -sI https://unth.ai | grep -iE "x-frame|x-content|permissions|referrer"
    ```
    All four headers must appear. If any are missing: check the Transform Rule in CF dashboard — verify it is deployed (green dot) and the header names/values are spelled correctly.
  </how-to-verify>

  <acceptance_criteria>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CF Transform Rule → HTTP response | CF injects headers after origin response — no origin code change needed |
| Browser → HSTS cache | After Stage 1 HSTS received, browser enforces HTTPS for 300s; after Stage 3 + preload, enforcement is permanent via browser preload list |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Clickjacking via iframe embed | mitigate | `X-Frame-Options: SAMEORIGIN` set via Transform Rule. Prevents third-party sites from iframing unth.ai. |
| T-03-02 | Tampering | MIME-type confusion attack | mitigate | `X-Content-Type-Options: nosniff` set via Transform Rule. Prevents browser from guessing MIME type. |
| T-03-03 | Spoofing | HTTP downgrade / MITM | mitigate | HSTS `max-age=300; includeSubDomains` — browser enforces HTTPS; staged to allow reversal if issue found. Plan 04 escalates to preload. |
| T-03-04 | Info Disclosure | Referrer leakage to third-party analytics or CDNs | mitigate | `Referrer-Policy: strict-origin-when-cross-origin` — sends only origin (not path) on cross-origin requests. |
| T-03-05 | Tampering | Sensor/camera/mic API abuse via embedded scripts or iframes | mitigate | `Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()` restricts all four APIs. |
| T-03-06 | Tampering | CF-level CSP breaking Cloudflare challenge pages | accept | CSP is intentionally NOT added to the Transform Rule. Meta-CSP in index.html provides partial coverage without CF conflict. Risk accepted — CSP via CF is a Phase 02+ concern. |
</threat_model>
