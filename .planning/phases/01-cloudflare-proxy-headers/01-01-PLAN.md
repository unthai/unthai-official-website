  <action>
    **Owner performs these two actions at Hostinger hPanel (both required before nameserver swap):**

    **Action A — Check DNSSEC status:**
    1. hPanel → Domains → unth.ai → DNS Zone
    2. Look for a "DNSSEC" section or tab
    3. If DNSSEC is ENABLED: disable it now and wait 24h before the nameserver swap in Plan 02 (DS records need time to expire from parent zone). Record status below.
    4. If DNSSEC is DISABLED or not present: proceed immediately.

    **Action B — Lower A record TTL to 300 seconds:**
    1. hPanel → Domains → unth.ai → DNS Zone
    2. Find the A record for `unth.ai` (apex / @ record) pointing to `145.223.108.64`
    3. Click Edit → change TTL from current value (likely 14400 or 3600) to `300`
    4. Save
    5. Find the A record for `www.unth.ai` pointing to `145.223.108.64`
    6. Click Edit → change TTL to `300`
    7. Save

    **Why this matters:** Existing DNS resolvers have cached the old TTL. After lowering to 300, resolvers will re-check every 5 minutes. Wait 24h after this step for the old TTL to fully expire across the internet before swapping nameservers in Plan 02. Swapping nameservers before waiting means some users will hit the old Hostinger records for up to the OLD TTL duration (potentially 4-14 hours).

    **Do NOT change MX record TTL** — email delivery uses MX, leave it alone.
    **Do NOT change NS records** — those are changed in Plan 02.
  </action>

  <how-to-verify>
    After owner action, run:
    ```bash
    # Verify new TTL is propagating (may take a few minutes)
    dig unth.ai A | grep -E "^unth.ai.*IN.*A"
    # Look for the number before "IN" — should now be 300
    ```
    Note: dig shows the TTL as seen by your local resolver. If it still shows the old TTL, wait 5-10 minutes and retry — the resolver is caching the old value and will update when it expires.
  </how-to-verify>

  <acceptance_criteria>

    - `dig unth.ai A | grep "IN.*A"` shows TTL value of 300 (may take up to old TTL to propagate)
    - `dig www.unth.ai A | grep "IN.*A"` shows TTL value of 300
    - MX record unchanged
  </acceptance_criteria>
